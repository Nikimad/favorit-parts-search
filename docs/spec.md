# Спецификация: подбор автозапчастей по артикулу

> Тестовое задание. Принцип: чем проще, тем лучше.

## 1. Цель

Клиентское React-приложение для двухэтапного подбора номенклатуры через API «Проценка» (Favorit Parts):

1. По артикулу найти производителей (брендов), выпускающих деталь.
2. По выбранному производителю показать искомую позицию и аналоги с названием, ценой и остатком.

## 2. Сценарий пользователя

1. Вводит артикул и нажимает Enter или кнопку «Найти». На пустом экране может кликнуть один из примеров артикулов.
2. Видит список производителей (бренд и название детали).
3. Выбирает производителя.
4. Видит искомую позицию отдельным блоком и под ней таблицу аналогов: название / производитель, цена, остаток.
5. Может выбрать другого производителя (блок и таблица обновятся) или ввести новый артикул (всё сбрасывается).

## 3. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | Поле ввода артикула. Значение обрезается по краям (`trim`). Пустой ввод не отправляется (кнопка отключена). |
| FR-2 | Запрос этапа 1 уходит по Enter или кнопке, а не на каждый символ (у API есть квоты). |
| FR-3 | Этап 1: запрос с `number` → список **уникальных** брендов из `goods[]` по алфавиту. |
| FR-4 | Список производителей: бренд и название детали. Клик выбирает бренд, выбранный подсвечивается. |
| FR-5 | Этап 2: при выборе бренда запрос с `number`, `brand`, `analogues=on`. Повторный клик по уже выбранному бренду запрос не повторяет. |
| FR-6 | Искомая позиция выводится отдельным блоком над таблицей с бейджем «Искомая»: название, бренд, артикул, цена, остаток. В таблицу аналогов она не входит. Таблица аналогов: **Название / Производитель**, **Цена**, **Остаток**; артикул второстепенной строкой под названием. Заголовок таблицы: «Аналоги: N, в наличии M». |
| FR-7 | Новый поиск (этап 1) сбрасывает выбранный бренд, искомую позицию и аналоги. |
| FR-8 | На каждом этапе показывается лоадер; на этапе 2 рядом с ним подпись «Ищем аналоги, это может занять до 10 секунд». Ошибки и пустые результаты обрабатываются по п. 5. В сообщении об ошибке (оба этапа) есть кнопка «Повторить», которая повторяет последний запрос. У информационных сообщений («ничего не найдено») кнопки нет. |
| FR-9 | Порядок аналогов: сначала с остатком, внутри группы по возрастанию цены, позиции без цены в конце группы. Пользовательской сортировки нет. |
| FR-10 | По умолчанию в таблице только аналоги с остатком. Под таблицей кнопка «Показать ещё K без наличия» раскрывает остальные, затем «Скрыть позиции без наличия». Если аналогов в наличии нет, над кнопкой строка «Аналогов в наличии нет». Смена бренда сворачивает список. |
| FR-11 | Пока поиск не выполнялся, под полем ввода строка-подсказка и два кликабельных примера артикулов: `7160500039S` и `0189`. Клик подставляет артикул и запускает поиск. После первого поиска подсказка скрывается. |
| FR-12 | Публичный деплой (Vercel): прокси-функция кэширует успешные ответы без `error` (`Cache-Control: s-maxage=300`), остальные ответы отдаёт с `no-store`. Запрос к API ограничен 12 с; при превышении пользователь видит сообщение из п. 5 и кнопку «Повторить». |

## 4. API-контракт (используемая часть)

Клиент вызывает `GET /api/hsprice`. Прокси (dev: Vite, prod: serverless-функция) переписывает путь на `http://api.favorit-parts.ru/hs/hsprice/` и добавляет `key`.

| Параметр | Этап 1 | Этап 2 |
|---|---|---|
| `number` | да | да |
| `brand` | нет | да (значение ровно как пришло из этапа 1) |
| `analogues` | нет | `on` |

Поля ответа, которые используем:

- Позиция: `goodsID`, `brand`, `number`, `name`, `count` (остаток на всех складах), `warehouses[]`, `analogues[]` (только этап 2).
- Склад: `price`, `stock`.

**Искомая позиция:** первая позиция верхнего уровня `goods[]` ответа этапа 2. **Аналоги:** все `analogues[]` без повторов по `goodsID` и без искомой.
**Правило цены:** минимальная `warehouses[].price` среди складов со `stock > 0`. Если таких складов нет, показываем «—».
**Правило остатка:** `count`. Если `count = 0`, позиция приглушена и помечена «Нет в наличии».
Валюта в документации не указана, поэтому цена выводится числом с двумя знаками без символа валюты.

Не используем: корневой `price`, `rate`, `info` / `notRefund`.

## 5. Состояния и ошибки

| Ситуация | Как распознаём | Что показываем |
|---|---|---|
| Загрузка | `status = loading` | Лоадер (Bootstrap spinner), на этапе 2 с подписью |
| Ничего не найдено, этап 1 | `goods` из одного элемента с нулевым `goodsID` / пустым `brand` | Инфо-сообщение «По артикулу «X» ничего не найдено» (не ошибка) |
| Ничего не найдено, этап 2 | После нормализации нет ни искомой позиции, ни аналогов | Инфо-сообщение «Для выбранного производителя предложений не найдено» |
| Ошибка API | В теле `{"error": ...}` (строка или массив) | Сообщение об ошибке и «Повторить». `Request quota exceeded!` → «Превышен лимит запросов, попробуйте позже». `Empty key!` / `Invalid key client!` / `Invalid access key` → «Ошибка конфигурации ключа API». Неизвестный текст показывается как есть |
| Таймаут на деплое | `{"error": "Request timeout!"}` от функции | «Сервис отвечает слишком долго. Повторите запрос» и «Повторить» |
| Сбой сети, не-2xx без `error`, невалидный JSON, `{"error": "Gateway error!"}` от функции | `fetch` отклонён, `!response.ok`, ошибка парсинга | «Не удалось связаться с сервисом. Проверьте соединение и повторите запрос» и «Повторить» |
| Нулевой остаток | `count = 0` | Позиция приглушена, «Нет в наличии» |
| Нет цены | Нет складов со `stock > 0` | «—» |

## 6. Вне рамок

Пользовательская сортировка и фильтры, пагинация, автопоиск, тесты компонентов, корзина и заказ, i18n, темизация, `info=on`, кратность (`rate`), состояние в URL.

## 7. Критерии приёмки

Примеры из документации датированы 2019 годом, поэтому живые данные могут отличаться. Проверяем структуру и поведение, а не конкретные числа.

| ID | Проверка |
|---|---|
| AC-1 | Артикул `7160500039S` → список с брендом MEYLE. После выбора есть блок «Искомая» и аналоги, у каждой строки есть название, бренд, цена, остаток. |
| AC-2 | Артикул `0189` → несколько брендов с разными названиями деталей. |
| AC-3 | Артикул `7260500039S` (не найден) → инфо-сообщение «ничего не найдено», без ошибки и без пустого списка. |
| AC-4 | При недоступном API / остановленном прокси лоадер исчезает и появляется сообщение о сбое. |
| AC-5 | Цена равна минимальной цене среди складов с остатком и никогда не берётся из корневого `price`. |
| AC-6 | Быстрый выбор бренда A, затем B: итоговые данные относятся к B. |
| AC-7 | Ключ API не встречается в `src/` и в запросах браузера (вкладка Network). |
| AC-8 | `npm install && npm run dev` (с `.env` из `.env.example`) работает; `npm test` зелёный; `npm run build` без ошибок. |
| AC-9 | Позиция с `count = 0` отображается приглушённой с пометкой «Нет в наличии»: искомая в блоке всегда, аналог в таблице после раскрытия списка. |
| AC-10 | Во время этапа 2 виден текст «Ищем аналоги…». Если остановить прокси, появляется ошибка с кнопкой «Повторить»; после запуска прокси клик по кнопке выполняет запрос и показывает данные. |
| AC-11 | Искомая позиция отдельным блоком над таблицей и в таблице отсутствует. Числа в заголовке «Аналоги: N, в наличии M» совпадают с содержимым. В таблице сначала позиции с остатком, цены по возрастанию. |
| AC-12 | По умолчанию видны только аналоги с остатком; число K на кнопке верное; после клика позиции без наличия появляются приглушёнными; смена бренда снова сворачивает список. |
| AC-13 | На чистом экране видны два примера, клик запускает поиск; после первого поиска примеры скрыты. |
| AC-14 | На деплое повторный одинаковый запрос к `/api/hsprice` попадает в кэш (`x-vercel-cache: HIT`: Vercel не показывает клиенту `s-maxage`), ответ с ошибкой (например, без `number`) приходит с `Cache-Control: no-store`. AC-1…AC-3 на деплое проходят. |
