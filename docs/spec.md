# Спецификация: подбор автозапчастей по артикулу

> Тестовое задание. Принцип: чем проще, тем лучше.

## 1. Цель

Клиентское React-приложение для двухэтапного подбора номенклатуры через API «Проценка» (Favorit Parts):

1. По артикулу найти производителей (брендов), выпускающих деталь.
2. По выбранному производителю показать искомую позицию и аналоги с названием, ценой и остатком.

## 2. Сценарий пользователя

1. Вводит артикул, нажимает Enter или кнопку «Найти».
2. Видит список производителей (бренд и название детали).
3. Выбирает производителя.
4. Видит таблицу: искомая позиция (помечена) и аналоги: название / производитель, цена, остаток.
5. Может выбрать другого производителя (таблица обновится) или ввести новый артикул (всё сбрасывается).

## 3. Функциональные требования

| ID | Требование |
|---|---|
| FR-1 | Поле ввода артикула. Значение обрезается по краям (`trim`). Пустой ввод не отправляется (кнопка отключена). |
| FR-2 | Запрос этапа 1 уходит по Enter или кнопке, а не на каждый символ (у API есть квоты). |
| FR-3 | Этап 1: запрос с `number` → список **уникальных** брендов из `goods[]`. |
| FR-4 | Список производителей: бренд и название детали. Клик выбирает бренд, выбранный подсвечивается. |
| FR-5 | Этап 2: при выборе бренда запрос с `number`, `brand`, `analogues=on`. Повторный клик по уже выбранному бренду запрос не повторяет. |
| FR-6 | Таблица: **Название / Производитель**, **Цена**, **Остаток**. Искомая позиция помечена бейджем «Искомая». Артикул показывается как второстепенная строка под названием. |
| FR-7 | Новый поиск (этап 1) сбрасывает выбранный бренд и таблицу. |
| FR-8 | На каждом этапе показывается лоадер; ошибки и пустые результаты обрабатываются по п. 5. |

## 4. API-контракт (используемая часть)

Клиент вызывает `GET /api/hsprice`. Прокси переписывает путь на `http://api.favorit-parts.ru/hs/hsprice/` и добавляет `key`.

| Параметр | Этап 1 | Этап 2 |
|---|---|---|
| `number` | да | да |
| `brand` | нет | да (значение ровно как пришло из этапа 1) |
| `analogues` | нет | `on` |

Поля ответа, которые используем:

- Позиция: `goodsID`, `brand`, `number`, `name`, `count` (остаток на всех складах), `warehouses[]`, `analogues[]` (только этап 2).
- Склад: `price`, `stock`.

**Правило цены:** минимальная `warehouses[].price` среди складов со `stock > 0`. Если таких складов нет, показываем «—».
**Правило остатка:** `count`. Если `count = 0`, строка приглушена и помечена «Нет в наличии».
Валюта в документации не указана, поэтому цена выводится числом с двумя знаками без символа валюты.

Не используем: корневой `price`, `rate`, `info` / `notRefund`.

## 5. Состояния и ошибки

| Ситуация | Как распознаём | Что показываем |
|---|---|---|
| Загрузка | `status = loading` | Лоадер (Bootstrap spinner) |
| Ничего не найдено, этап 1 | `goods` из одного элемента с нулевым `goodsID` / пустым `brand` | Инфо-сообщение «По артикулу «X» ничего не найдено» (не ошибка) |
| Ничего не найдено, этап 2 | После нормализации нет ни позиции, ни аналогов | Инфо-сообщение «Для выбранного производителя предложений не найдено» |
| Ошибка API | В теле `{"error": ...}` (строка или массив) | Сообщение об ошибке. `Request quota exceeded!` → «Превышен лимит запросов, попробуйте позже». `Empty key!` / `Invalid key client!` → «Ошибка конфигурации ключа API» |
| Сбой сети, не-2xx, невалидный JSON | `fetch` отклонён, `!response.ok`, ошибка парсинга | «Не удалось связаться с сервисом. Проверьте соединение и повторите запрос» |
| Нулевой остаток | `count = 0` | Строка приглушена, «Нет в наличии» |
| Нет цены | Нет складов со `stock > 0` | «—» |

## 6. Вне рамок

Пользовательская сортировка и фильтры, пагинация, автопоиск, тесты компонентов, корзина и заказ, i18n, темизация, `info=on`, кратность (`rate`), состояние в URL. Исключение: расширения из п. 9.

## 7. Критерии приёмки

Примеры из документации датированы 2019 годом, поэтому живые данные могут отличаться. Проверяем структуру и поведение, а не конкретные числа.

| ID | Проверка |
|---|---|
| AC-1 | Артикул `7160500039S` → список с брендом MEYLE. После выбора в таблице есть позиция «Искомая» и аналоги, у каждой строки есть название, бренд, цена, остаток. |
| AC-2 | Артикул `0189` → несколько брендов с разными названиями деталей. |
| AC-3 | Артикул `7260500039S` (не найден) → инфо-сообщение «ничего не найдено», без ошибки и без пустого списка. |
| AC-4 | При недоступном API / остановленном прокси лоадер исчезает и появляется сообщение о сбое. |
| AC-5 | Цена в таблице равна минимальной цене среди складов с остатком и никогда не берётся из корневого `price`. |
| AC-6 | Быстрый выбор бренда A, затем B: итоговая таблица относится к B. |
| AC-7 | Ключ API не встречается в `src/` и в запросах браузера (вкладка Network). |
| AC-8 | `npm install && npm run dev` (с `.env` из `.env.example`) работает; `npm test` зелёный; `npm run build` без ошибок. |
| AC-9 | Позиция с `count = 0` отображается приглушённой с пометкой «Нет в наличии» (в таблице аналогов после раскрытия списка, см. E-3; искомая позиция показывается всегда). |

## 9. Расширения (после T8)

> Добавляются поверх готовой базовой версии (перед началом: `git tag v1-spec`). Раздел дополняет п. 3 и п. 5 и заменяет FR-6 в части выделения искомой позиции (E-2). Реализация: `docs/plan.md`, п. 10. Задачи: T10–T15 в `docs/tasks.md`.

| ID | Требование |
|---|---|
| E-1 | **Долгая загрузка и повтор.** На этапе 2 рядом со спиннером подпись «Ищем аналоги, это может занять до 10 секунд». В сообщении об ошибке (оба этапа) есть кнопка «Повторить», которая повторяет последний запрос. У информационных сообщений («ничего не найдено») кнопки нет. |
| E-2 | **Искомая позиция и порядок.** Искомая позиция выводится отдельным блоком над таблицей и в таблицу аналогов не входит. Заголовок таблицы: «Аналоги: N, в наличии M». Порядок аналогов: сначала с остатком, внутри группы по возрастанию цены, позиции без цены в конце группы. Пользовательской сортировки нет. |
| E-3 | **Свёртка позиций без наличия.** По умолчанию в таблице только аналоги с остатком. Под таблицей кнопка «Показать ещё K без наличия» (раскрывает, затем «Скрыть позиции без наличия»). Если аналогов в наличии нет, над кнопкой строка «Аналогов в наличии нет». Смена бренда сворачивает список. |
| E-4 | **Пустой экран.** Пока поиск не выполнялся, под полем ввода строка-подсказка и два кликабельных примера артикулов: `7160500039S` и `0189`. Клик подставляет артикул и запускает поиск. После первого поиска подсказка скрывается. |
| E-5 | **Только если выполнен деплой (T9).** Функция кэширует успешные ответы (`Cache-Control: s-maxage=300`), ответы с ошибкой не кэшируются. Запрос к API ограничен по времени: при превышении пользователь видит понятное сообщение и кнопку «Повторить». |

Критерии приёмки расширений (AC-1…AC-9 должны оставаться выполненными):

| ID | Проверка |
|---|---|
| AC-10 | E-1: во время этапа 2 виден текст «Ищем аналоги…». Если остановить прокси, появляется ошибка с кнопкой «Повторить»; после запуска прокси клик по кнопке выполняет запрос и показывает данные. |
| AC-11 | E-2: искомая позиция отдельным блоком над таблицей и в таблице отсутствует. Числа в заголовке «Аналоги: N, в наличии M» совпадают с содержимым. В таблице сначала позиции с остатком, цены по возрастанию. |
| AC-12 | E-3: по умолчанию видны только позиции с остатком; число K на кнопке верное; после клика позиции без наличия появляются приглушёнными; смена бренда снова сворачивает список. |
| AC-13 | E-4: на чистом экране видны два примера, клик запускает поиск; после первого поиска примеры скрыты. |
| AC-14 | E-5 (только при T9): повторный одинаковый запрос к функции на деплое возвращает `Cache-Control: s-maxage=300`, а ответ с ошибкой (например, номер не передан) возвращает `no-store`. AC-1…AC-3 на деплое по-прежнему проходят. |
