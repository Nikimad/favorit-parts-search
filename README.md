# Подбор автозапчастей

Клиентское приложение на React для двухэтапного подбора запчастей через API «Проценка» (Favorit Parts): по артикулу находит производителей, по выбранному производителю показывает искомую позицию и аналоги с ценой и остатком.

## Запуск

```bash
npm install
cp .env.example .env     # в .env.example тестовый ключ из документации API
npm run dev              # http://localhost:5173
npm test                 # юнит-тест нормализации ответа API
npm run build
```

В Windows (cmd) вместо `cp` используйте `copy .env.example .env`. Примеры артикулов: `7160500039S` (один производитель, много аналогов), `0189` (несколько производителей), `7260500039S` (ничего не найдено).

## Как это устроено

- Стек: Vite, React (JavaScript), Redux Toolkit, Bootstrap 5 (только CSS), Vitest.
- Приложение обращается только к `/api/hsprice`. Ключ добавляет прокси: в dev `vite.config.js`, на деплое serverless-функция `api/hsprice.js`. В клиентский код ключ не попадает.
- Два Redux-слайса: `search` (этап 1) и `offers` (этап 2). Устаревшие ответы отбрасываются по `requestId`.
- Разбор ответа API собран в `src/api/normalize.js` и покрыт тестом.
- Искомая позиция выводится карточкой над таблицей аналогов. Аналоги идут сначала в наличии, затем по цене; позиции без наличия свёрнуты под кнопкой.

Структура, состояние и компоненты: [`docs/plan.md`](docs/plan.md). Версия строго по исходному заданию сохранена тегом `v1-spec`.

## Допущения и нюансы API

- Цена берётся из `warehouses[].price` (минимум среди складов с остатком), а не из корневого `price`: документация помечает его как устаревший.
- Остаток: поле `count` (сумма по всем складам).
- «Не найдено» API возвращает как массив из одного пустого элемента, а не ошибкой. Приложение показывает это как информационное сообщение.
- Ошибки API приходят как `{"error": ...}`, в том числе с HTTP 200, поэтому проверяется тело ответа.
- Поиск запускается по Enter или кнопке, а не на каждый символ: у API есть квоты.
- Валюта в документации не указана, поэтому цена показывается без символа валюты.
- Примеры в документации датированы 2019 годом, живые данные могут отличаться.
- Порядок аналогов в ответе меняется от запроса к запросу, поэтому приложение упорядочивает их само. Искомой считается первая позиция верхнего уровня ответа, дубли аналогов отбрасываются.
- Ответ этапа 2 бывает большим: для `7160500039S` / MEYLE около 740 позиций (~1,4 МБ), из них в наличии около 475. Позиции в наличии выводятся целиком, без пагинации.

## Что сделал бы при большем бюджете

- Свой ключ API вместо общего демо-ключа и лимит запросов по IP в функции.
- Урезание ответа на сервере: отдавать клиенту только нужные поля, а не ~1,4 МБ сырого JSON.
- Кратность (`rate`) и невозвратные позиции (`info=on`).
- Срок поставки (`shipmentDate`) рядом с ценой и остатком.
- Быстрый выбор «дешевле / быстрее» среди аналогов.
- Фильтры по аналогам (производитель, наличие, цена) и пользовательская сортировка.
- Состояние поиска в URL, чтобы ссылкой можно было поделиться.
- Карточки вместо таблицы на мобильном.
- Кнопки «В корзину» / «Запросить цену».
- Аналитика пустых поисков: какие артикулы ищут и не находят.
- Автопоиск с debounce (сейчас запрос только по Enter или кнопке, чтобы не тратить квоту).
- Пагинация или виртуализация длинной таблицы аналогов.
- Тесты компонентов.

## Деплой

Демо: https://favorit-parts-search-three.vercel.app/ — **общий тестовый ключ: квоту запросов делят все, кто открыл ссылку**, поэтому возможно сообщение «Превышен лимит запросов».

- Функция `api/hsprice.js` пропускает только `number`, `brand`, `analogues` и добавляет ключ из переменной окружения `FAVORIT_API_KEY` (задаётся в настройках проекта Vercel).
- Успешные ответы кэшируются на 5 минут (`s-maxage=300`), ответы с ошибкой не кэшируются. Запрос к API ограничен 12 с, `vercel.json` задаёт функции `maxDuration: 15`.
- Проверено на деплое: функция отвечает `goods`, API доступен из региона Vercel по умолчанию, бренд `NGK/NTK` доходит без искажений, ключа нет ни в бандле, ни в URL запросов, AC-1…AC-3 выполняются. Самый тяжёлый запрос (`7160500039S` / MEYLE) занимает 4–7 с.
- **Статус:** демо по ссылке работает на версии без кэша и таймаута (повторный запрос даёт `x-vercel-cache: MISS`, ошибка приходит без `no-store`). После передеплоя попадание в кэш проверяется по `x-vercel-cache: HIT`: Vercel не показывает клиенту `s-maxage`.
