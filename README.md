# Подбор автозапчастей

Клиентское приложение на React для двухэтапного подбора запчастей через API «Проценка» (Favorit Parts):

1. Ввод артикула → список производителей.
2. Выбор производителя → таблица искомой позиции и аналогов (название / производитель, цена, остаток).

## Стек

Vite, React (JavaScript), Redux Toolkit, Bootstrap 5 (CSS), Vitest.

## Запуск

```bash
npm install
cp .env.example .env     # в .env.example тестовый ключ из документации API
npm run dev              # http://localhost:5173
npm test                 # юнит-тест нормализации ответа API
npm run build
```

## Как это устроено

- Приложение обращается к `/api/hsprice`. В dev-режиме прокси Vite перенаправляет запрос на `http://api.favorit-parts.ru/hs/hsprice/` и подставляет ключ из `.env`. Ключ не попадает в клиентский код, а прокси заодно снимает проблемы CORS и mixed content (API работает по `http://`).
- Состояние: два Redux-слайса (`search` для этапа 1, `offers` для этапа 2) со статусами `idle | loading | succeeded | failed`. Устаревшие ответы отбрасываются по `requestId`.
- Все разборы ответа вынесены в `src/api/normalize.js` и покрыты тестом.

## Допущения и нюансы API

- Цена берётся из `warehouses[].price` (минимум среди складов с остатком), а не из корневого `price`: документация помечает его как устаревший.
- Остаток: поле `count` (сумма по всем складам).
- «Не найдено» API возвращает как массив из одного пустого элемента, а не ошибкой. Приложение показывает это как информационное сообщение.
- Ошибки API приходят как `{"error": ...}`, возможно с HTTP 200, поэтому проверяется тело ответа.
- Поиск запускается по Enter или кнопке, а не на каждый символ: у API есть квоты.
- Валюта в документации не указана, поэтому цена показывается без символа валюты.
- Примеры в документации датированы 2019 годом, живые данные могут отличаться.
