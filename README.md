# Подбор автозапчастей

Клиентское приложение на React для двухэтапного подбора запчастей через API «Проценка» (Favorit Parts):

1. Ввод артикула → список производителей.
2. Выбор производителя → таблица искомой позиции и аналогов (название / производитель, цена, остаток).

## Возможности

Базовая версия строго по заданию сохранена тегом `v1-spec`. Поверх неё сделаны расширения (`docs/spec.md`, п. 9):

- **Долгая загрузка и повтор.** На этапе 2 рядом со спиннером подпись «Ищем аналоги, это может занять до 10 секунд». В ошибке на любом этапе есть кнопка «Повторить», она повторяет последний запрос. У сообщения «ничего не найдено» кнопки нет.
- **Искомая позиция отдельно.** Она выводится карточкой над таблицей и в таблицу аналогов не входит. Заголовок таблицы: «Аналоги: N, в наличии M».
- **Порядок аналогов.** Сначала позиции с остатком, внутри группы по возрастанию цены, без цены в конце группы. Пользовательской сортировки нет.
- **Свёртка позиций без наличия.** По умолчанию в таблице только аналоги с остатком, остальные раскрываются кнопкой «Показать ещё K без наличия». Смена бренда снова сворачивает список.
- **Примеры на пустом экране.** Пока поиск не выполнялся, под полем видны артикулы `7160500039S` и `0189`: клик подставляет артикул и запускает поиск.
- **Кэш и лимит времени на деплое.** См. раздел «Деплой».

## Стек

Vite, React (JavaScript), Redux Toolkit, Bootstrap 5 (CSS), Vitest.

## Запуск

```bash
npm install
cp .env.example .env     # в .env.example тестовый ключ из документации API
npm run dev              # http://localhost:5173
npm test                 # юнит-тест нормализации ответа API
npm run build
```

В Windows (cmd) вместо `cp` используйте `copy .env.example .env`. Примеры артикулов для проверки: `7160500039S` (один производитель, много аналогов), `0189` (несколько производителей), `7260500039S` (ничего не найдено).

## Как это устроено

- Приложение обращается к `/api/hsprice`. В dev-режиме прокси Vite перенаправляет запрос на `http://api.favorit-parts.ru/hs/hsprice/` и подставляет ключ из `.env`. Ключ не попадает в клиентский код, а прокси заодно снимает проблемы CORS и mixed content (API работает по `http://`).
- Состояние: два Redux-слайса (`search` для этапа 1, `offers` для этапа 2) со статусами `idle | loading | succeeded | failed`. Устаревшие ответы отбрасываются по `requestId`.
- Все разборы ответа вынесены в `src/api/normalize.js` и покрыты тестом.

## Допущения и нюансы API

- Цена берётся из `warehouses[].price` (минимум среди складов с остатком), а не из корневого `price`: документация помечает его как устаревший.
- Остаток: поле `count` (сумма по всем складам).
- «Не найдено» API возвращает как массив из одного пустого элемента, а не ошибкой. Приложение показывает это как информационное сообщение.
- Ошибки API приходят как `{"error": ...}`, возможно с HTTP 200, поэтому проверяется тело ответа.
- Поиск запускается по Enter или кнопке, а не на каждый символ: у API есть квоты.
- Валюта в документации не указана, поэтому цена показывается без символа валюты.
- Примеры в документации датированы 2019 годом, живые данные могут отличаться.
- Порядок аналогов в ответе меняется от запроса к запросу, поэтому приложение упорядочивает их само (наличие, затем цена). Искомой считается первая позиция верхнего уровня ответа, дубли аналогов отбрасываются.
- Ответ этапа 2 бывает большим: для `7160500039S` / MEYLE около 740 позиций (~1,4 МБ), из них в наличии около 475. Позиции в наличии выводятся целиком, без пагинации.

## Что сделал бы при большем бюджете

- Свой ключ API вместо общего демо-ключа и лимит запросов по IP в функции.
- Урезание ответа на сервере: отдавать клиенту только нужные поля, а не ~1,4 МБ сырого JSON.
- Кратность (`rate`) и невозвратные позиции (`info=on`).
- Срок поставки (`shipmentDate`) рядом с ценой и остатком.
- Быстрый выбор «дешевле / быстрее» среди аналогов.
- Фильтры по аналогам (производитель, наличие, цена) и пользовательская сортировка.
- Состояние поиска в URL, чтобы ссылкой можно было поделиться.
- Карточки вместо таблицы на мобильном.
- Кнопки «В корзину» / «Запросить цену».
- Аналитика пустых поисков: какие артикулы ищут и не находят.
- Автопоиск с debounce (сейчас запрос только по Enter или кнопке, чтобы не тратить квоту).
- Пагинация или виртуализация длинной таблицы аналогов.
- Тесты компонентов.

## Деплой

> ⚠️ **Опционально.** Деплой не входил в требования задания.

Демо: https://favorit-parts-search-three.vercel.app/ — **демо-версия на общем тестовом ключе: квоту запросов делят все, кто открыл ссылку**, поэтому возможно сообщение «Превышен лимит запросов».

- В prod роль dev-прокси выполняет serverless-функция `api/hsprice.js`: пропускает только `number`, `brand`, `analogues` и добавляет ключ из переменной окружения `FAVORIT_API_KEY` (задаётся в настройках проекта Vercel).
- Проверено на деплое: функция отвечает `goods`, API доступен из региона Vercel по умолчанию (отдельный `vercel.json` не понадобился), бренд `NGK/NTK` доходит без искажений, ключа нет ни в бандле, ни в URL запросов, AC-1…AC-3 выполняются. Самый тяжёлый запрос (`7160500039S` / MEYLE, ~1,4 МБ) занимает 4–7 с.
- При сбое upstream функция отвечает пустым 502, интерфейс показывает сообщение о сбое. Это проверено подменой ответа в браузере, реальный отказ API на Vercel не воспроизводился.

### Кэш и лимит времени (расширение E-5)

- Успешные ответы без `error` функция отдаёт с `Cache-Control: s-maxage=300`, остальные с `no-store`: API присылает ошибки и с HTTP 200, такие ответы кэшировать нельзя.
- Запрос к API ограничен 12 с. При превышении функция отвечает `504 {"error":"Request timeout!"}`, интерфейс показывает «Сервис отвечает слишком долго. Повторите запрос» и кнопку «Повторить».
- Сетевой сбой upstream даёт `502 {"error":"Gateway error!"}`, интерфейс показывает сообщение о недоступности сервиса.
- `vercel.json` задаёт функции `maxDuration: 15` (больше таймаута, в пределах лимита тарифа Hobby).
- Vercel вырезает `s-maxage` из заголовка, который видит клиент. Попадание в кэш проверяется по `x-vercel-cache: HIT` на повторном одинаковом запросе.
- **Статус:** ветки функции проверены локально на подменённом `fetch`. Демо по ссылке пока работает на версии до E-5 (повторный запрос даёт `MISS`, ошибка приходит без `no-store`), поэтому AC-14 на деплое не проверен.
